# istok_unified — объединённый бот (трекер доплат + поиск попутчиков)

Слияние двух ботов в один: **трекер карпула/доплат** (как раньше) + **поиск
водителя** для сотрудников. Собран на базе трекера, точечно доработан.

## Что делает

**Трекер доплат (как раньше):** водитель регистрируется, добавляет пассажиров,
еженедельная проверка, ежедневные снапшоты → GAS сверяет с табелями → `Svodka`.

**Новое:**
- У водителя при регистрации спрашивается **город** (City+State из списка `cities`),
  подхватывается **Username** и telegramID.
- **🔍 Найти водителя** — сотрудник (проверка имени по `employees`) ищет водителей
  по **городу** или **штату**, получает контакты (машина, телефон, `t.me/username`).
- **Двойная роль:** зарегистрированный водитель может ехать пассажиром у другого,
  если у него **нет своих пассажиров**. Как только добавляет своих — авто-отвязка
  из чужого карпула.
- **Еженедельный expire** больше не удаляет водителя — только чистит его пассажиров.

## Доступ
Всё — только для сотрудников из `employees`. Регистрация водителя по роестру;
поиск с проверкой имени (проверенные помнятся в памяти процесса, ничего не пишется).

## Google Sheets (новая схема)

| Лист | Колонки |
|---|---|
| `employees` | Name · Phone Number · Shift · Rides with · **DriverTGID** *(было telegramID)* |
| `drivers` | Name · telegramID · **Username** · Phone Number · Shift · **City** · **State** · Car · Plates · isActive |
| `drivers_passengers` | Name · telegramID · Phone Number · Shift · Passenger1..4 |
| `cities` | City · State *(справочник поиска)* |
| week1–4, табели, `Svodka`, `Svodka Columbus`, `_anomalies`(+columbus), `_manual_adjustments` | как раньше |

**Мигрированная таблица** с реальными данными: `istok_unified_migrated.xlsx`
(employees дедуплицированы, `DriverTGID` переименован, `DAYS`/`_rides_log` убраны).

## GAS
`istok_unified_gas.gs` — тот же расчёт доплат + все правки сессии (раздельные
`Svodka`/Columbus, даты из имени листа, очистка аномалий, обработчик таймаутов,
правило зачёта, отключённая авто-очистка смены), плюс `employees` tgid-заголовок
= `DriverTGID`. Вставляется в Apps Script таблицы.

## Переменные окружения (Railway)

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | **токен трекера** (сотрудники им уже пользуются) |
| `SPREADSHEET_ID` | ID новой таблицы |
| `GOOGLE_CREDENTIALS` | JSON сервис-аккаунта |
| `ADMIN_USER_IDS` / `ADMIN_CHAT_ID` | админы / чат для логов |
| `PAGE_SIZE`, `*_SHEET`, `CITIES_SHEET` | опционально |

## Запуск / деплой
```
pip install -r requirements.txt
python bot.py
```
Railway worker: `worker: python bot.py`. Один экземпляр (polling). Rideshare-бот
(`istok_bot`) выводится из эксплуатации — его функция теперь здесь.

## Порядок внедрения
1. Загрузить `istok_unified_migrated.xlsx` на Диск → **сохранить как Google Таблицу**.
2. Расшарить её сервис-аккаунту (Редактор).
3. Вставить `istok_unified_gas.gs` в Apps Script таблицы, настроить триггеры.
4. В Railway у трекер-сервиса заменить `SPREADSHEET_ID` на новую таблицу, задеплоить этот код.
5. Существующие водители при следующей регистрации/обновлении добавят город.
